# BNF 매매법 백테스트 (국내 대형주 급락 매매) — v6

## 목표

**v6부터 기본은 "사장님 규칙"(2026-10-03 확정)** — 실제로 쓸 매매 규칙을 그대로 시뮬레이션한다:
1. 10시: 코스피 시총 상위 200 우량주 중 전일 대비 -5% 이하(급락 스캔)
2. 14시50분: 그 종목이 여전히 -5% 이하면 매수. 종목당 100만원 이내 최대 수량, 1주가 100만원 넘으면 1주. 하루 매수 종목 수 제한 없음(사장님 확인)
3. 장중 -4% 닿으면 즉시 손절, +10% 닿으면 즉시 익절(사장님 확인: 장중 즉시)
4. 둘 다 아니면 3거래일째 매도(월→목, 금→수. 휴일은 거래일이 아니라 자동으로 하루씩 밀림)

아래 v5 비교(급락5%/BNF원전 × 매수시점 × 손절방식)는 참고용으로 계속 남겨둔다.

코스피 시가총액 상위 개별 우량주를 대상으로 두 가지 매수 신호(사장님이 지정한 "급락5%" 변형 규칙 vs BNF 리서치로 확인한 "BNF원전" 방식)를 매수 시점(9시30분/마감30분전)·손절 방식(이전 저점/-5%/-8%)별로 종합 비교하고, 시장 전체 패닉 여부와 세전/세후 수익률까지 따져서 HTML 리포트로 확인한다.

## 필요한 입력값 (사장님께 확인)

- **분석 기간**: 시작일 ~ 종료일 (기본값: 올해 2월 1일 ~ 오늘)
- **급락5% 기준**: 전일 대비 등락률 몇 % 이하 (기본값: -5%, `app/config.py`의 `DROP_THRESHOLD_PCT`)
- **BNF원전 기준**: 이격도(기본 80=-20%, `DISPARITY_BUY_MAX`, 최근 `BNF_INDICATOR_WINDOW_DAYS`일 내)/RSI(기본 35로 완화, `BNF_RSI_MAX`, 같은 윈도우)/MACD 당일 전환 — 완화 폭은 사장님이 직접 확인 후 확정(2026-09-24)
- **매수 시점**: 9시30분(장시작 30분후)/마감30분전(15시) — 사장님이 직접 지정(2026-09-24)
- **유니버스 크기**: 시가총액 상위 몇 종목까지 (기본값: 200, `app/config.py`의 `TOP_N`)
- **손절선 기준일수**: "이전 저점" 룩백 일수 (기본값: 20거래일, `STOP_LOSS_LOOKBACK_DAYS`)

## 실행할 Tool

0. **사장님 규칙만** 빠르게 돌릴 때(약 10분):
   ```
   python -m tools.bnf_backtest --owner-only
   ```
   - `simulate_owner_rule()`: 일봉 저가가 -5%도 안 간 날은 후보에서 빼고, 남은 날만 10시(`OWNER_SCAN_TIME`)·14시50분(`OWNER_ENTRY_TIME`) 체결가를 조회.
   - `_simulate_owner_exit()`: 일봉 시가/고가/저가로 장중 손절·익절 판정. 갭하락/갭상승이면 시가에 체결, 같은 날 손절선·익절선을 둘 다 찍으면 순서를 알 수 없어 **보수적으로 손절** 처리. 매수 당일 종가가 이미 -4% 이하면 당일 손절.
   - 결과: `.tmp/bnf_owner_trades.csv`(수량·투입금액·원 단위 손익 포함), `.tmp/bnf_owner_capital.csv`(거래일별 보유 종목 수·필요 자금), `.tmp/bnf_owner_meta.json`(최대 필요 자금 등)
   - 옵션 없이 실행하면 사장님 규칙 + v5 비교를 모두 돌린다(약 30분).

1. `tools/bnf_backtest.py` — 실제 매매 시뮬레이션, 원본 트레이드 데이터 생성
   ```
   python -m tools.bnf_backtest
   ```
   - `app/kis_client.py`(KIS API), `app/universe.py`(유니버스, ETF/ETN/리츠 제외), `app/indicators.py`(이격도·RSI·MACD·손절가, 시리즈 버전 포함)를 재사용한다.
   - **신호 2종** (`signal_mode`):
     - `급락5%`: 전일 대비 진입시각(9시30분/마감30분전) 등락률 <= `DROP_THRESHOLD_PCT`. 신호 당일 매수.
     - `BNF원전`: 최근 `BNF_INDICATOR_WINDOW_DAYS`(10)거래일 내 이격도<=`BNF_DISPARITY_MAX`(80) AND 같은 기간 내 RSI<`BNF_RSI_MAX`(35) AND 그날 MACD 히스토그램 음→양 전환. 신호는 종가로만 확정되므로 **다음 거래일**에 매수.
       (주의: 처음엔 "이격도<=80·RSI<30·MACD전환이 전부 같은 날"로 구현했는데 200종목·8개월간 신호가 2건뿐이었음 — 대형주는 RSI가 그렇게까지 안 빠지는 데다, MACD 전환 자체가 반등이 어느 정도 진행된 뒤에야 나오는 후행 신호라 이격도·RSI 저점 시점과 잘 안 겹친다. 이격도 기준(-20%)은 유지하고 RSI·타이밍만 완화했다 — 여러 완화 수준을 실제 데이터로 미리 계산해서 사장님께 추천안을 드리고 확인받은 뒤 적용함.)
   - **매수 시점 2종** (`entry_mode`): `9시30분`(장시작 30분후, "093000") / `마감30분전`(15시, "150000") — KIS 시간별시세 API로 실제 조회(`app/kis_client.py::get_intraday_price_at()`, `ENTRY_TIME_STR` 딕셔너리에서 시각 매핑). 다른 시각도 이 딕셔너리에 항목만 추가하면 바로 확장 가능.
   - **손절 3종** (`stop_loss_mode`, 같은 신호에 추가 API 호출 없이 동시 계산): `이전저점` / `고정-5%` / `고정-8%`.
   - **시장 패닉 태깅** (`market_panic`): 신호일에 코스피 지수도 `MARKET_PANIC_KOSPI_DROP_PCT`(-1.0%) 이하로 빠졌는지. 업종지수가 더 정확하지만 종목별로 추가 조회해야 해서 코스피 지수로 근사.
   - **세후 근사** (`return_pct_after_fee`): 세전 수익률에서 `ROUND_TRIP_FEE_PCT`(0.2%p) 단순 차감.
   - 결과: `.tmp/bnf_backtest_trades.csv`(트레이드 원본, `signal_mode`/`entry_mode`/`stop_loss_mode`/`market_panic` 컬럼으로 구분), `.tmp/bnf_backtest_meta.json`(진행 통계는 `am_stats`에 신호별·매수시점별로 들어있음)

2. `tools/bnf_html_report.py` — 집계 + HTML 리포트 생성
   ```
   python -m tools.bnf_html_report
   ```
   - 결과: `.tmp/bnf_backtest_report.html` — `bnf_owner_*` 파일이 있으면 맨 위에 "사장님 규칙" 섹션(승률, 원 단위 총손익, 최대 필요 자금, 월별 손익, 자금 많이 필요했던 날 Top10, 시장패닉 비교, 베스트/워스트)이 붙는다. v5 비교 파일(`bnf_backtest_trades.csv`)도 있어야 실행된다.
   - 맨 위에 "신호×매수시점 4가지 조합" 핵심 지표 비교표(손절은 이전저점 기준), 그 아래 각 조합별 상세(손절방식 비교, 시장패닉 비교, 청산사유별, 승패비율, 월별 추이, 베스트/워스트, 진행중 포지션).
   - Claude가 Artifact로도 게시해서 링크 전달.

## 문제 발생 시 대응

- **"토큰 발급 제한 초과(EGW00133)" 에러**: KIS 접근 토큰은 1분에 1회만 새로 발급 가능. `get_access_token()`이 프로세스 전역 변수로 캐시하므로 백테스트 실행 중엔 1번만 발급된다. 직전에 다른 스크립트로 테스트했다면 1분 이상 기다렸다 재실행.
- **일부 종목 "일봉 조회 실패"**: `.tmp/bnf_backtest_meta.json`의 `failed_tickers` 확인. 너무 많으면(10개 이상) 토큰 문제부터 의심.
- **실행 시간**: 종목별 체결가 조회를 `ThreadPoolExecutor`로 병렬화(`INTRADAY_WORKERS`/`DAILY_FETCH_WORKERS`, 기본 16)해서 200종목 기준 **20~25분**. 처음엔 순차 호출로 짰다가 90분이 넘게 걸려서(사장님이 "너무 오래 걸린다"고 지적) 병렬화로 고쳤다 — 대신 워커 수가 높으면 가끔 "초당 거래건수 초과"(EGW00201)로 소수 종목(200개 중 5개 안팎)의 일봉 조회가 실패할 수 있다. 실패율이 더 늘면 `INTRADAY_WORKERS`/`DAILY_FETCH_WORKERS`를 낮출 것(예: 16->10). `.tmp/bnf_backtest_meta.json`의 `am_stats`에서 신호·매수시점별 후보일/실신호 수를 확인할 수 있다.
- **BNF원전 신호가 너무 적음**: 버그가 아니라 실제로 그럴 수 있다(위 "신호 2종" 설명 참고). 신호가 0에 가까우면 리포트에서 해당 조합 섹션이 비어있는 채로 나오는데, 이 자체가 "이 기간엔 원전 기준 매매 기회가 드물었다"는 유효한 결과다.

## 알아둘 가정/한계

- (v6 사장님 규칙) 장중 손절/익절은 일봉으로 근사 — 실제 체결은 호가·슬리피지 때문에 손절이 -4%보다 조금 더 깊게 나갈 수 있다. 만기 매도는 3거래일째 **종가** 기준.
- (v6) 같은 종목은 보유 중이면 다시 사지 않는다(종목당 동시 1포지션). 필요 자금은 "매수 직후 보유 중인 종목 투입금 합계"로 근사(그날 팔린 종목은 매수 전에 팔렸다고 봄).

(이하 2026-09-24 v5 기준)

- 유니버스는 **코스피 시가총액 상위 200개, 개별주만**(ETF/ETN/리츠펀드 등 `그룹코드!=ST`는 제외 — `app/universe.py` 참고). **코스닥은 아직 미포함**: `kosdaq_code.mst`가 `kospi_code.mst`와 필드 구조가 달라서(정상 거래 종목이 "거래정지"로 잘못 파싱되는 걸 확인) 정확한 스펙을 확인하기 전까진 코스피만 쓴다.
- 유니버스는 **현재 시점 스냅샷**을 과거에 소급 적용 (그 당시 실제 상위 200개와 다를 수 있음).
- 수익률은 **세전이 기본**, 세후는 근사치(위 참고).
- 종목당 **동시 1포지션만** — 4가지 (신호×매수시점) 조합은 서로 독립적으로 포지션 관리.
- "이격도100_익절"/"이격도 조건" 청산은 이름과 달리 개별 트레이드 단위로는 손실인 경우도 있다(기술적 조건일 뿐 항상 이익을 보장하지 않음).
